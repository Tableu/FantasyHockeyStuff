# Season

The season simulator — section 6 of the Fantasy Hockey AI build plan, and the evaluation harness
section 16 needs. Four modelling layers were built before it, each validated against its own job:

```
ModelFeatures/   447 features, leakage asserted        "is this feature knowable at the lock?"
Projections/     a mean per player-game, and per ROS   "how close is this projection?"
Simulation/      a distribution, calibrated            "is this spread right?"
Season/          a won week                            "does using any of it beat not using it?"
```

Nothing before this folder asks the last question. That is the gap this closes.

**It opens no database.** Like `Projections/` and `Simulation/`, everything arrives by path. It is
the first folder that imports *code* from a sibling — `Simulation/`'s sampler, copula and scoring —
because drawing a night is a computation rather than a file. That dependency lives in `simlayer.py`
and nowhere else, and it is narrower than it looks: `Simulation/simulate.py` and `correlations.py`
**cannot** be imported at all, because `Season/paths.py` shadows `Simulation/paths.py` under the
flat-module convention both folders use. The two fitted JSONs they would have supplied are read by
path instead, which is how every other layer here consumes the one below it.

**It measures; `Decisions/` chooses.** Every policy the ladder seats -- the four rungs, the lineup
solver, the draft rule, rung 3's box-score estimator -- lives in the sibling `Decisions/` folder so
a live runner can use the same code a backtest scored. It is reached through `decisionlayer.py`,
which refuses to start if a module name in `Decisions/` also exists here or in `Simulation/`.

```
paths.py      where every input lives
league.py     the format as data: slots, bench, IR, the move cap, the playoff shape
schedule.py   game days and Mon-Sun matchup weeks, derived from the schedule, never assumed
inputs.py     the loaders, and the provenance assertion that makes the measurement honest
state.py      rosters, IR, the free-agent pool, waivers, the weekly move counter
view.py       SlateView -- the only thing a manager sees
draftroom.py  the draft as an event: seat order, the snake; the pick itself is Decisions/draft.py
simlayer.py   the bridge to Simulation/, and the module-name collision it works around
decisionlayer.py  the bridge to Decisions/ (managers, slots, draft, estimators)
engine.py     the day loop: lock, resolve, accumulate by week
ladder.py     CLI                                          -> reports/ladder_<season>.json
report.py     the results as prose                         -> docs/ladder-<config>.md
compare.py    two formats against each other, paired
verify.py     the six checks that have to pass before a number means anything
```

## Running it

```bash
pip install -r requirements.txt

# once, from ModelFeatures/ -- the only steps that touch the database
python build_goalie_starts.py --season 2023-24 --season 2024-25 --season 2025-26
python build_fantasy_positions.py --platform Yahoo --season 2026-27 --adp

# once, from Projections/ -- rung 4 reads this
python goalie_starts.py --train --save --predict --season 2025-26

python ladder.py --season 2025-26 --weights points-league --weights banger-league \
    --replications 8 --decision-sims 120
python ladder.py --league league-12team-simple --replications 8 \
    --weights points-league --weights banger-league
python compare.py --a league-12team-simple --b league   # what a format change does
python verify.py         # provenance, leakage, draws, invariants, assignment, calendar
```

## What the ladder measured

`docs/ladder.md` carries the table, generated by `report.py`. Six seat rotations, three clones a
rung, so each rung is a mean over 18 team-seasons of the real 2025-26 schedule. Outcomes are the
actual stat lines, so there is no Monte Carlo noise in them; the spread below is across seats.

| points-league | points / week | ±SE | win rate | decision eff. | wasted slot-nights | moves |
|---|---|---|---|---|---|---|
| 1 — autodraft, never look again | 134.10 | 2.09 | 0.333 | 0.798 | 999 | 0 |
| 2 — start every healthy player | **157.82** | 1.97 | **0.614** | 0.949 | 50 | 0 |
| 3 — capped streamer, box-score rate | 146.64 | 5.92 | 0.513 | 0.942 | 89 | 154 |
| 4 — full system | 147.94 | 3.44 | 0.540 | 0.940 | 67 | 154 |

Paired inside each league instance, which is the only fair way to difference two rungs that shared a
schedule and a free-agent pool:

| | points-league | banger-league |
|---|---|---|
| rung 2 − rung 1 — attention | **+23.73 ± 2.10** | **+48.26 ± 4.59** |
| rung 3 − rung 2 — naive streaming | **−11.18 ± 3.52** | +1.21 ± 3.82 |
| rung 4 − rung 2 — the full system | **−9.88 ± 2.02** | −5.28 ± 4.24 |
| rung 4 − rung 3 — *the modelling stack* | +1.30 ± 3.12 | −6.50 ± 6.33 |

### Section 16's question, answered

> *Full system. Projections, Monte Carlo, orchestrator. If it doesn't clear rung 3 decisively, the
> modeling investment isn't paying for itself.*

**It does not clear rung 3.** +1.30 ± 3.12 points a week in the target format, −6.50 ± 6.33 in a
banger league. Neither is distinguishable from zero, and one has the wrong sign. By this section's
own standard, on this season and in this configuration, **the modelling investment is not paying for
itself in won weeks.**

Three effects do clear the noise, and all three are about attention rather than accuracy:

- **Setting a lineup daily is worth +23.7 points a week** in the target format and +48.3 in a banger
  league. It costs no transactions and no models. It is the whole game.
- **Spending the seven-move budget is actively harmful in the target format** — −11.2 a week naive,
  −9.9 with the full stack — and neutral in a banger league (+1.2 ± 3.8).
- Rung 1 is a floor by a wide margin, as section 16 predicted.

### What rung 4 does do

It is better than rung 3 at exactly what it was built to be better at, and it does not convert.
It wastes **67** slot-nights on players who did not dress against rung 3's **89** — the fitted
P(plays) working as designed — and it is far steadier: ±3.4 points a week across seats against rung
3's ±5.9. A naive streamer is not merely worse, it is erratic.

The binding constraint is not projection quality. It is that **the free-agent pool is the leftovers
of a twelve-team draft**, so every acquisition trades talent for games. Better rankings choose the
least-bad version of a bad move; they do not make it a good one. And the format gives the lineup
half nothing to work with either: only about half the NHL plays on a given night, so a sixteen-man
roster has roughly **seven** startable players against twelve active slots. No manager here ever
fills a lineup, so there is rarely a choice to get right — decision efficiency is already 0.94–0.97
against the hindsight-optimal lineup from the same roster.

With transactions switched off, all three attentive policies are level: rung 2 159.4, rung 3 160.4,
rung 4 158.9. **Everything after attention is worth nothing in the lineup.**

### Two methodological warnings, which may outlast the result

**An ablation sized this wrong by a factor of eighteen.** An earlier field put rung 4 ahead of rung 3
by 23 points a week. That field had eight of twelve seats playing modelled managers, all competing
for the same free agents, which starved rung 3 of anything worth adding. In the mixed round-robin
section 16 specifies, the gap is +1.3 ± 3.1. Because every rung shares one pool, **a rung's measured
performance is a property of the field and not of the strategy.** Ablations are for *attributing* a
result — they correctly located rung 3's deficit in its transactions, and that still holds — never
for sizing one.

**A gap without an error bar is an invitation to misread it.** `report.py` now prints every rung-vs-
rung difference paired inside each league instance, with its standard error, and states in words
whether it clears the noise. The first version printed bare differences and that is precisely how
the 23-point claim survived as long as it did.

## The format matters more than the model

`compare.py` runs the same season under two formats. Both at eight seat rotations, both scoresets,
identical everything else:

```
A  12 teams   2C 2LW 2RW 4D 2G          12 active, 4 bench, 22 weeks   rosters/league-12team-simple.json
B  14 teams   2C 2LW 2RW 1F 4D 1F/D 2G  14 active, 4 bench, 26 weeks   rosters/league.json
```

`F` accepts any forward and `F/D` any skater, so B has two **composite** slots. Points per week are
not comparable across formats — 14 active slots outscore 12 by construction — so what follows is the
gap *between rungs*, paired inside each league instance.

| points-league | A: 12-team simple | B: 14-team composite |
|---|---|---|
| attention (rung 2 − 1) | +25.37 ± 1.93 **clear** | +23.78 ± 1.27 **clear** |
| naive streaming (3 − 2) | −14.03 ± 4.20 **clear** | −16.00 ± 1.55 **clear** |
| full system vs not transacting (4 − 2) | −9.16 ± 2.35 **clear** | −7.01 ± 2.53 **clear** |
| **the modelling stack (4 − 3)** | +4.87 ± 4.43 *noise* | **+8.99 ± 1.98 clear** |

**In format B the modelling stack clears rung 3 decisively, which is the first time section 16's bar
has been met.** The point estimate nearly doubles and the standard error halves. Under banger-league
scoring the same gap moves from −2.33 ± 8.44 to +5.79 ± 4.46 — same direction, still inside the
noise.

Three properties of format B all push the same way, which is why the effect is as large as it is:

- **More slots to fill.** Fourteen active against the same seven or eight startable players a night,
  so the marginal slot-night is worth more and picking a player who actually dresses matters more.
  That is precisely rung 4's edge: a fitted P(plays) against rung 3's counted dress share.
- **Composite slots reward a good acquisition and forgive a positional mismatch.** An added skater
  can land in `F` or `F/D` rather than being stranded behind a full C slot. Rung 2's empty
  slot-nights fall from 45.8 to 35.9 and rung 4's from 62.8 to 43.5.
- **A deeper league leaves a shallower pool.** 252 rostered of ~1,072 against 192, so the free agents
  worth having are scarcer and telling two marginal ones apart is worth more.

**What does not change: not transacting still beats transacting.** Rung 2 leads rung 4 by 7.01 ± 2.53
points a week in B, clear of the noise. The seven-move budget is still a net cost in this format; the
modelling stack makes it a smaller one. And attention is still the dominant effect by a factor of
three.

So the honest reading is that **the modelling investment pays for itself against a streaming
opponent, and still loses to a manager who simply sets his lineup and leaves the wire alone.** The
format made the first half true; it did not make the second half false.

### What this says about measuring any of it

The verdict on the same code, the same season and the same models reversed on a roster-format
change. A result here is a statement about a *format*, not about the models — so the config file
being data rather than constants is not tidiness, it is what made the question askable at all. Two
formats are two measurements, which is also why report paths are now keyed by config: a shared
filename silently destroyed a measurement twice in this project before that was fixed.

## The goalie model

`Projections/goalie_starts.py`, the one goalie output that survived measurement. Held out of
2025-26 entirely, since the harness consumes it:

| | holdout AUC |
|---|---|
| **the model** | **0.876** |
| season start share | 0.721 |
| dressed share | 0.646 |
| "he started the last one" | 0.518 |

Well calibrated too — a predicted 0.030 starts 2.9% of the time, a predicted 0.943 starts 94.2%.
`start_share_edge` and `start_share_rank` take 43% of the fitted gain between them, which is the
design point: **a start is a contest inside a team-game, not a property of a goalie**, so the
informative features are relative ones. Predictions are normalized within team-game because
exactly one goalie starts.

Nothing here predicts how well a goalie will play, and that is deliberate: per-start points
measured at R² −0.8% and save percentage carries at r = +0.026. The line is the league average,
and it is **computed from the scoring file rather than hard-coded** — under points-league a start
is worth 4.39 with a spread of 4.03, under banger-league 3.59 and 3.31, and under a
goals-and-assists-only format −3.02, where a goalie is a liability rather than an asset.

## What is honest about these numbers, and what is not

**The projections are out of sample.** `inputs.py` reads `predictions_A.parquet`, the holdout
build's scored season, and refuses `lambdas_2025-26_A.parquet` — which is produced by whatever
boosters sit in `Projections/models/`, currently the deployment build trained on all three seasons
and therefore in-sample on the season being replayed. Handing that to rung 4 and a box-score rate
to rung 3 would compare a manager who has seen the results against one who has not.

**A manager cannot see outcomes.** Not by convention: `view.SlateView` raises on any column
matching `target_*`, `label_*` or the goalie line, so adding a field to the view cannot quietly
smuggle one through.

**Injuries are persistent and exogenous.** `injured_at_lockout` is the real season's history, so a
player out for six weeks is out for six weeks and IR is a real lever. Without it availability
would be a memoryless nightly coin flip and injury replacement — most of real streaming — would
not exist.

**Three known approximations, all measured:**

- Short-handed points are set to zero, because `predictions_A.parquet` predates that model. They
  are 0.38% of skater scoring (496 of 129,177 points on 396 of 46,654 played rows) and the
  understatement is identical for every manager. `inputs.py` has the rebuild that removes it.
- Twelve of 1,312 games are outside the simulated season, all of them 7–9 October: variant-A
  features need a previous game, so the candidate universe starts a few days in.
- Positional eligibility is Yahoo's for 2026-27 applied to 2025-26. It only widens which lineups
  are legal, and it widens them for everyone at once. **ADP is not treated this way** — a 2026-27
  draft board encodes 2025-26 results, so the draft uses a 2024-25 points ranking instead.

**Free IR flatters the do-nothing strategy.** Two IR slots, stashing that costs no move, and an
injury layer taken from the real season mean a manager who never transacts barely suffers for
injuries — he parks the injured and carries on. In a league with tighter IR, or none, the
transaction rungs would look better than they do here. The comparison is fair within this
configuration and should not be read past it.

**One season is one season, and six rotations only average the draft.** Outcomes here are the real
2025-26 lines, so rotating seats varies draft position and field interaction but not what the
players did. A ±3-point standard error is the spread across seats, not a confidence interval on
"would this strategy win next year". Phase 3's sampled outcomes are what would give that.

**Not covered.** Multi-replication with sampled outcomes, trades, and the live lockout snapshot
job. A win rate here is field-relative — all rungs sit in one league and play each other, so
removing a rung moves everyone's — and a single season is a single season. `points_per_week` is
the portable number until phase 3 puts error bars on both.
